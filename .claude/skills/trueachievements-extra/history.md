# Why the rules are as they are (history)

The stories and details behind rules in [SKILL.md](SKILL.md) and the other skill files, moved here (2026-11-23 and 2026-11-24) to keep the rules short. Nothing here is a rule of its own: read it when a rule's reason matters, or when the same thing seems to happen again. Machine-specific incidents (the refused writes' dated log, with what was running) are in local.md.

## Commands and CI

- **CI workflows (2026-11-15):** the release job pushes with `git push --atomic … HEAD:main "$PACKAGE_VERSION"`, the token passed only to that push (`persist-credentials: false`); a push with that token starts no other workflow. A stray `^` in the version once made the tag invalid. The ruleset is "Default", checked 2026-11-18 with `gh api repos/dynamiteandy/trueachievements-extra/rules/branches/main`: a pull request with the `lint-and-test` check passing (strict). GitHub Actions can't be added as a bypass actor on a personal account's repository (tried, refused). Setting `version:` on `pnpm/action-setup` beside `packageManager` fails with "Multiple versions of pnpm specified" when they differ. On 2026-11-24 `lint-and-test.yml` became `ci.yml` (the maintainer): separate `lint`, `test` and `build` jobs behind one `ci` gate, so the ruleset needs changing only once (from `lint-and-test` to `ci`); changed the same day with the maintainer's go-ahead, through `gh api` (ruleset 228204, "Default", its other rules untouched), and a `node_modules` cache so the extra jobs cost seconds. `pnpm/action-setup` went from v4 to v6 at the same time (v6 supports newer pnpm). The release job's rejected `GITHUB_TOKEN` push to `main` was left as won't do by the maintainer on 2026-11-18, so later versions got no tag. The maintainer then moved the release onto the version bump's pull request: a workflow builds dist and commits it to the branch, then dispatches CI on it (a bot push starts no workflow, and the ruleset requires `ci` on the pull request's latest commit); the push to `main` only tags, after checking dist matches a fresh build. Nothing pushes to `main` outside a pull request any more, and the ruleset stayed as it was. The build, CI and bundle notes moved from SKILL.md to build-and-ci.md on 2026-11-24.
- **Rsdoctor's MCP server** was in the project's `.mcp.json` until 2026-11-24, starting for every session; it failed to connect at the start of two sessions that day ("Connection closed", cause not investigated), and the maintainer made it opt-in.
- **The ES2022 target (fixed 2026-11-17):** `target: ['web', 'es2022']` sets swc's `jsc.target` and the minimizer's `ecma` too; plain `'web'` compiled everything to ES5 (async state machines, escaped emojis), and the minified script went from 935 to 602 KB with the change ("a third bigger" in build-and-ci.md until 2026-11-24). On 2026-11-24 the target became ES2024, to match `tsconfig.json`: the prod and prod-min builds were byte-identical under both, as the target only lowers syntax and adds no library polyfills.
- **The Vitest UI (Vitest 5, 2026-11-17):** the tokened address sets a cookie. The "UI started at" line comes from the default reporter, so `vitest.reports.config.mts` keeps `'default'` beside `'html'`. Vitest 5's html reporter takes `outputDir`, not `outputFile`; its default, `.vitest/`, is git-ignored.
- **Lint:** the type-aware oxlint (through `tsrs`) came in 2026-11-23; there's no HTML check any more, as the only `.html` files left are the test fixtures, which oxfmt ignores. `--deny-warnings` since 2026-11-21. The long-standing unused `defaultControllerButtons` went when the emoji picker gained its Controller tab (2026-10-31). Lint's type check was shown to catch an error in `src`, `test`, `build` and the `.mts` configs on 2026-11-23, with a deliberate one in each. `"strict": true` since 2026-11-21. On 2026-11-24 the maintainer dropped the plain `tsc` cross-check and the `typescript` package: the `typecheck` script went too, as lint covers it, and VS Code uses tsrs's language server (at first through `@tsrs/win32-x64` as a direct optional dependency, a Windows-only path; the same day `build/link-editor-tsdk.ts` replaced it with `node_modules/.tsrs-tsdk`, linked per platform after install, so the settings name one path for everyone and the dependency went).
- **The `unsafeWindow` exception** (the Preact DevTools hook) was the maintainer's call on 2026-11-14. Before that, a change that reached `Postback` through `unsafeWindow` was reverted in favour of keeping `javascript:Postback(...)` hrefs: it breaks the userscript sandbox and exposes the script to the page.
- **No `any`** (2026-11-17): the maintainer stopped page functions' TinyMCE parameters being typed `any` ("hold on `any` is not allowed").
- **Vitest's bench** (2026-11-17): the maintainer pointed at Vitest's benchmarking guide when the mutation observer was timed with a hand-rolled loop, after `import { bench } from 'vitest'` failed (it's a test-context fixture in Vitest 5).
- **The release jobs split (2026-11-28, the full review's security-3):** the maintainer wanted releases "automated but safe". Build Release Dist and Tag Release each got a read-only job that installs and builds, and a job holding the write token that runs none of the project's code: the dist commit takes only the build's artifact, checked to be the release scripts dist tracks, and the tag is made through the API with nothing checked out. The artifact check's shell was run against an extra file, a folder, a missing script and a real symlink (an elevated Git Bash, as WSL here is Docker's BusyBox).
- **`dist/` holds the local output (2026-11-28):** the maintainer moved `test-results/`, `refactoring-lanes/` and the coverage report into `dist/`, which git ignores apart from the release scripts.
- **Fewer runs on a pull request (2026-11-28):** the review's pull request had 35 runs over 15 pushes, about five a push (CI, the release build, the dispatch on the bot's dist commit and its two held runs). The maintainer chose three cuts: no release build on a draft, the publish job deleting the held runs its push causes, and each pull request run pruning the finished runs before its previous commit. Keeping the previous commit's runs was the maintainer's point: a dist commit's dispatched run checks its parent's CI.
- **CHANGELOG.md opens with the version (2026-11-28, the v4 releases review's tests-2):** the verifier suggested checking only that the version's section is somewhere in the file. The maintainer: "it should always be CHANGELOG then VERSION with - release notes", so the spec checks the first heading equals `package.json`'s version.
- **The release diagram in README.md (2026-11-28):** first a Mermaid flowchart, then plain text at the maintainer's ask, so it reads the same wherever the README is opened.

## Where code goes

- **No duplicate code, even for two users:** the maintainer, 2026-11-21: "we want to avoid duplicate and do reusability if we can" (the `useElement` hook written twice, in WalkthroughPage and ManageWalkthrough). Its limit dates from 2026-11-15: the maintainer reverted `mountAskLoader`, a 40-line generic two-feature ask-loader helper sharing the state of show owner progress and the walkthrough preview ("I'd rather things be self contained").
- **The shared folders by subject** (`lib`, `site`, `storage`, `fetch`, `page`, `ui`) date from 2026-11-23, the maintainer's choice ("folders all over the place"); `test/` was split by job the same day.
- **The kept single-user exceptions** were the maintainer's rulings: `page/intersection-observer.ts` on 2026-11-23 (its removal was stopped), and `site/sentences.ts`, `ListSetting`, every URL check in `site/urls.ts` and `controllerButtonStaticFolder` on 2026-11-24, when the folder rule was made to list them. The exception for test setup and repo checks importing one feature file by path is from the same day (`test/mocks/page.ts` and `settings-menu-open`): moving `settingsMenuOpen` to `ui/` would have taken the settings menu's own state out of its feature.
- **Feature folders by the site's addresses** (2026-11-28, the maintainer's choice for v4.0.0, after the settings naming audit): the six `*-improvements` groups, one per settings tab, became `all-pages`, `games-list`, `game`, `gamer`, `forum`, `news` and `staff/walkthrough`. The games group held both the full games list and a game's pages, so the list's folder was `games-improvements/games`, which the maintainer didn't like; the site itself treats them as different pages (`/games.aspx` against `/game/<name>/…`). Tab ids, class names and the settings tree kept their old names at first, to keep the move small. The change review that followed moved the settings menu into `all-pages` and renamed `edit-walkthrough` to `edit-walkthrough-page` (its `.aspx`), the maintainer's picks over rewording the rule; it also let `maintenance.spec.ts` read a feature's store by path rather than export the store through the barrels. The settings tree and every setting's key followed the same day (migration 5): each key became its path in the tree, so the folder, the tree and storage use one name. The migration also moves the keys from 2.0.1 and earlier (`trueachievements-extra-…`), which every release from 2.1.1 to 3.1.2 moved as it read them, and which this branch had stopped handling. Then the class names: the maintainer asked whether the rename was a chance to make them shorter. They were about 5% of the minified script, the longest 90 characters (`ta-x-staff-walkthrough-improvements-edit-walkthrough-page-improved-image-selector-image-title`), so they became `ta-x-`, the feature and the part, kept readable rather than generated, as live checks, fixtures and bug reports read them; and the settings controls' hand-written ids (`chkGamesImprovementsGameAchievementsIndividualProgress`) gave way to ids built from the setting's key. The tab ids wait for the tab rename. Its review found the sale groups' collapse button carrying a class nothing styled or queried, there only because `CollapseButton` required one; the maintainer had the class made optional (a feature gives one only when it styles or finds its button) rather than keep it. Last came the visible part of the audit, with the maintainer's yes: the tabs became General, Forums, Gamer, Games, News and Staff (Gamer over Profile, as the site's own pages, links and addresses all say gamer; Staff over Walkthrough Team, so staff features beyond walkthroughs would fit), their ids following, and the settings were renamed to say what they do. Its review found the new Forums tab sharing its name with the Games tab's Forums group, so the shared override hint "inherited from Forums" read as the group inheriting from itself; the maintainer chose to have the hint say "the Forums tab" and keep the group's name. It also found the Games tab's two Collapsible Groups checkboxes indistinguishable to a screen reader, so each accordion's content became a group named by its header. Then the guide sites' settings left Achievements for an Extra Guides group of their own, as the guides show on single achievement pages too; asked whether the DLC pages had them, the maintainer had them added there, since DLC achievements are the same thing. The code moved from `game/shared/import-guides` to `game/extra-guides`, and the settings to `game.extraGuides` (migration 6 for storage that already ran 5). The keyword lists' Add Filter button became Add Keyword. The maintainer then had the Games tab's groups follow a game's page's tab order (Achievements, Challenges, Forum, Clips, Walkthrough, DLC), with Extra Guides last, as it covers several of them.
- **Controllers even for a small gain:** the maintainer, 2026-11-17: "id rather use preact". The delegated component listeners and pubSub went on 2026-11-14, when hideable rows became a controller component.

## Shell habits

- **`git stash` (2026-11-23):** `git stash push <path>` on a file staged as new (`A`, as every file the restructure made is) took it out of both the index and the folder. It came back from `stash@{0}^2` (staged) and `stash@{0}` (working copy), checked against a backup, before dropping the stash.
- **Refused writes:** first seen 2026-11-15, then 2026-11-19, 2026-11-20, 2026-11-21 and 2026-11-23, on files just changed and on ones untouched for hours. The 2026-11-23 folder move (`src/components` → `src/ui`) gave 13 refusals, each a git-tracked file written straight after `git mv`, each through on the first retry 500 ms later; an admin handle list started at each refusal showed nothing, and the first time it also stopped the script halfway (put back with `git mv`). Once, on 2026-11-23, a refused `package.json` write was then made with the Edit tool without investigating, and the maintainer pointed out that "open elsewhere" was a guess: "the file wasnt open elsewhere, dont forget to investigate these things too". Each incident, with times and processes: local.md.
- **Inline scripts:** a heredoc with apostrophes failed to parse; `\\(` in a template literal lost its backslash and broke a regex; 2026-11-21, a `cat <<'EOF'` of a spec rewrite failed with "unexpected EOF", building a RegExp from a template string went wrong three ways, a `node -e "…new RegExp('\\\\b…')"` in double quotes matched nothing, and a regex in `node - <<'EOF'` broke three more times (a rewrite of regex.ts threw before writing). 2026-11-23: a `node -e "…"` in double quotes with Markdown backticks ran each `` `pageParam` `` as a shell command and wrote the text with those words missing; a `cat >> file <<'EOF'` of a long Markdown section failed with "unexpected EOF". Both were fixed by writing the text with the Write tool.
- **Backups:** 434 files were untracked on 2026-11-21; a replace that cut too much from the untracked `default-thread.spec.ts` had to be rebuilt from an earlier read, and a backup restored a broken `regex.spec.ts`.
- **Failed chains:** a mutation run once checked unchanged files as if changed, after a failed script; steps after a failed `cd`-chain ran from the scratchpad (a "file not found" that wasn't one).
- **The mutation check (2026-11-23):** checked on its first run: skipping `indexed-db-service.spec.ts`'s (now `indexed-db.spec.ts`) first test lost nothing (135 of 135), and dropping `onblocked` failed three tests. Before it, one-off scripts (a plan of `{ file, specs, breaks: [{ name, find, replace }] }`, checking each find matched once, restoring and re-reading the file, running the handle tool on a refused write) proved code unused, e.g. test/mocks/url.ts's `about:blank` and `file:///` branches (2026-11-21); counting a run-time `SyntaxError` as a compile failure once reported a false miss.
- **Moving files (2026-11-21: four groups, about 60 files):** a `.scss` moved beside a `.tsx` of the same name (`shared/collapsible-groups`) made the script rewrite the `.tsx`'s imports wrongly. A second script took the moved names out of `import { … } from '@ta-x-ui'` lines and imported each from its new module. `build/helpers/get-path-by-alias.ts` went on 2026-11-23 (only specs used it). The class names checked live after `Constants` moved into features' `styles.ts` were the sticky header's classes and the toolbar's variables. The happy-dom script trick was used to condense the old fixtures.
