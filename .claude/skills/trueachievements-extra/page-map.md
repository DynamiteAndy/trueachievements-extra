# Page map

Which TrueAchievements page each feature runs on. Use it to find the page to open (the example URL), and to find the feature folder that changes a given page.

- **Check** is the URL test the feature runs, from `src/site/urls.ts` (`<Group>Regex.Test.<name>()`). A feature runs only where its check passes.
- **Folder** is relative to `src/features/` (unless it starts `src/`) and follows the page's address (SKILL.md, "Where code goes"). Its settings sit at the same path in `storage/settings-tree.ts`, which is also their storage key (`game/achievements`: `settings.game.achievements`, `game.achievements.defaultStatus`).
- **Keep this up to date** when a feature's URL check changes, or a feature folder is added or moved.

### Switching states: Preact DevTools

- **State a component owns** (its `useState`, or a signal like the settings menu's open state or `toastMessage`): change it with Preact DevTools (dev builds hand it the hook). In the extension's panel, or from the page console (how agents do it, from `javascript_tool`):

  ```js
  const r = [...window.__PREACT_DEVTOOLS__.renderers.values()][0];
  const id = r.findVNodeIdForDom(element); // the component that rendered element
  r.inspect(id).hooks.filter((h) => h.editable); // its state, e.g. { name: 'useState', meta: { index: 0 }, value: true }
  r.updateHook(id, 0, false); // sets that state (hook index 0), e.g. collapses an accordion
  ```

  On an achievement group's collapse button, `false` sets its content to `max-height: 0`, `true` puts it back. A signal a component reads changes with `r.updateSignal(id, <its index in inspect(id).signals>, value)`, e.g. the toast's `{ text: 'Hello', type: 'success' }` shows a toast (DevTools then throws `i.setState is not a function` on a function component, after the change has applied: ignore it). A component with no DOM of its own (`GuideSitePanel`, `OwnerProgressSection`, `PreviewAside`, and `HideableRow`, whose parts are portals) isn't what `findVNodeIdForDom` finds, and DevTools gives no id for it from the console (the panel's tree shows it fine). From the console, walk up from a child's vnode to it and call its state setter (dev builds only; `__` is the parent vnode, `__c.__H.__[i].__` hook `i`'s `[value, setter]`):

  ```js
  let vn = r.getVNodeById(r.findVNodeIdForDom(element)); // any element it renders
  while (vn && r.getDisplayName(vn) !== 'OwnerProgressSection') vn = vn.__;
  const [value, set] = vn.__c.__H.__[0].__;
  set({ status: 'ask' }); // later set(value) puts back what it had found
  ```

- **What DevTools can't switch** is checked by its real trigger (a real giveaway page, a real save) and by its spec; there are no dev commands (components.md → "Every state checkable live").

- **Secret achievements** (the forum's list of them: `viewthread.aspx?tid=36122`): the site marks them `ul.ach-panels li[data-secret]` on a game's list and `.ach-panel[data-secret]` on an achievement page, with a "SECRET …" overlay until clicked (`.show`). **Only when it hides them from the viewer:** signed out, Alan Wake 2 marks 48 of its 88 (e.g. `/a410896/the-trail-of-the-writer-achievement`), while a signed-in account with "Show secret achievements I don't have" on sees none marked. The built-in browser (its own profile, signed out) shows the marked markup but has no Tampermonkey, so our script doesn't run there (signed-out checks: live-site.md → "Opening a page"). **To see them hidden in the user's own Chrome:** `/customize.aspx`, Site Settings, Achievements, "Show secret achievements I don't have" (local.md says how the user keeps it). It's a switch that saves at once (no Save button): switch it without asking, check, then switch it back and reload to confirm, as with the theme (SKILL.md → "Rules"). With it off, Alan Wake 2's `/a410896/the-trail-of-the-writer-achievement` has its panel marked.

| ------------------------------ | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| XboxAchievements game guide    | `https://www.xboxachievements.com/game/<name>/guide/`                                               | `ExternalRegex.Test.xboxAchievementsGuide` (host and path)    | `game/extra-guides/read-guide-page.ts` (hands the guides over; the achievement page shows them) |

On a guide site our script's console isn't visible to you, so check it worked from the TrueAchievements achievement page, or add temporary `document.documentElement.dataset` markers. Forget a game's saved guide page with its row's remove link in the site's tab. Switch a site's tab between ask, import and importing with Preact DevTools (its `GuideSitePanel`'s state). ### Gamer

| Page               | Example URL                      | Check                                  | Folder                                  |

A gamer's games list (`/gamer/<gamertag>/games`, table `#oGamerGamesList`) and game collection (`/gamer/<gamertag>/gamecollection`) only show signed in (signed out: "Please log in to view this gamers games"). Use them to find a game in a given state for a check (part-won, fully won, not played); local.md lists the user's.

Game forum default thread: with it on (and not All Threads), links to a game's forum without a tab get `?type=<value>` on every page (`game/forum/default-thread-links.ts`), so the hub's Forum tab opens straight on it; a forum reached another way (a typed URL, a bookmark) still clicks the tab once.
